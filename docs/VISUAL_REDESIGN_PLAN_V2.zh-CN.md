# DSH-OS26 V2 全面视觉重构计划

## 结论

当前 `0.1.0-beta.1` 的工程安全性合格，但视觉方案不合格，不应按现状发布视频或作为公开版本主视觉。

两张实机截图暴露出的根本问题不是“玻璃参数还不够强”，而是目前只完成了全局配色、状态胶囊和设置页局部表单，没有建立覆盖 DSH 核心界面的组件系统。最终效果因此更像“淡蓝色主题滤镜”，而不是层级明确、控件一致、交互连续的 Liquid Glass 界面。

V2 的目标不是继续堆高模糊和透明度，而是重做材质、几何、控件、状态和排版五个层面。输入框必须成为主视觉，原生按钮与插件设置控件必须属于同一套语言，文字溢出必须有统一规则。

## 截图问题审计

### P0：发布前必须修复

1. **输入框仍是原生白色卡片**
   - 外轮廓、输入区、工具行、模型选择、发送按钮没有形成一体化玻璃容器。
   - 当前 `ComposerDock` 只在输入框下方添加状态文字，没有改变输入体验。
   - 状态胶囊与输入框相距过远，像两个互不相关的插件。

2. **全局蓝色蒙层破坏层级**
   - 侧栏、内容区和会话区接近同一明度、同一色相。
   - 大面积淡蓝背景降低文字对比，同时让真正的玻璃边缘失去参照物。
   - 壁纸颜色应该只通过局部透射影响材质，不应把整页染蓝。

3. **设置控件仍是浏览器默认观感**
   - checkbox、select、range、按钮的形状、边框和状态语言不一致。
   - range 只有蓝色实线与普通圆点，没有玻璃轨道、折射高光、数值反馈或按压状态。
   - 白色大卡片与顶部玻璃 Hero 割裂。

4. **文本溢出与信息拥挤**
   - 会话标题、任务状态、模型名、统计行在窄宽度下相互挤压。
   - 设置项标题、说明、数值和控件没有明确的收缩优先级。
   - 当前部分组件只做单行省略，没有 tooltip、换行上限或移动端布局切换。

5. **通用按钮没有被纳入系统**
   - 新会话、顶部操作、输入区加号、权限、模型、发送、关闭、设置页操作仍各说各话。
   - hover、pressed、focus、disabled、busy 缺少统一的深度与光学反馈。

### P1：完成后才有视频辨识度

- 侧栏选中态只是普通浅色块，没有玻璃焦点层。
- 会话内容区缺少前景、中景、背景三层关系。
- 工具执行、审批、完成状态虽然有独立胶囊，但没有与输入框连续变形或共享光源。
- 设置弹窗的背景模糊存在，但内部导航、内容卡片和控件没有同一材质逻辑。
- 深色、浅色、窄屏和高缩放场景尚未形成可展示的成套画面。

## V2 视觉方向

### 1. 从“蓝色皮肤”改为“中性画布 + 局部透色”

- 页面基础色回归中性冷灰，浅色不再铺满淡蓝。
- 壁纸只从侧栏、composer、弹窗、浮层等玻璃表面透出。
- 强调色只用于当前操作、进度和状态，不作为所有表面的底色。
- 浅色模式优先保证白、灰、墨色层级；深色模式使用石墨黑和冷灰，而不是纯藏蓝。

### 2. 建立 Glass Primitive System

所有表面和控件只从以下原语组合，不再为单个组件临时写一套渐变：

| 原语 | 用途 | 关键特征 |
| --- | --- | --- |
| `canvas` | 页面底层 | 中性、不透明、承载壁纸光斑 |
| `glass-panel` | 侧栏、设置弹窗、大面板 | 低色偏、柔和透射、双层边缘 |
| `glass-card` | composer、工具卡、设置组 | 更高不透明度、局部高光、清晰阴影 |
| `glass-control` | select、按钮、chip、slider thumb | 小尺度高对比、按压深度、明确焦点 |
| `glass-accent` | 发送、当前状态、危险操作 | 局部颜色与辉光，不污染相邻表面 |

每个原语至少包含：填充层、顶部高光、暗侧内阴影、外边缘、环境阴影和无透明回退。`backdrop-filter` 只是其中一层，不再被当作“液态玻璃”的全部。

### 3. 几何与间距

- 主容器圆角使用 24–30px，卡片 18–22px，控件 12–16px，胶囊使用全圆角。
- 统一 4px 间距基线和 44px 最小交互高度；纯图标按钮视觉尺寸可小于 44px，但命中区不得小于 40px。
- 玻璃边缘保持 1px 双亮暗结构，避免所有卡片都是相同白线。
- 阴影分为贴面、悬浮和模态三个高度，不再每个组件都使用同一个大阴影。

## 组件级改造清单

### A. Composer：本轮第一主角

1. 直接重塑原生 `[data-composer-card]`，覆盖完整卡片而不是只添加 dock。
2. 使用 `[data-input-scroll]`、`[data-input-backdrop]` 和原生 `textarea` 完成透明输入层、占位文字、选区、禁用和滚动边缘处理。
3. 把工具行纳入同一张玻璃卡：加号、权限、Plan、附件、模型选择、发送/停止拥有共同高度和 pressed 反馈。
4. 发送按钮改为高折射 accent orb；停止状态连续变形为 stop control，不通过突然换一枚无关按钮完成。
5. 状态只保留一个主来源：常态融入 composer 边缘或状态岛；审批、阻塞、错误时再展开为明确面板。
6. 输入聚焦时只提升边缘亮度和局部透射，不做整卡强烈发光。
7. 多行输入、附件轨、命令菜单、只读、无工作区、steer/queue、运行中和错误提示都必须单独验收。

**默认技术路线：**保留 DSH 原生 composer 业务逻辑，使用官方 Token 加稳定语义属性做兼容样式。只有视觉验收仍不达标时，才使用官方 `conversation.composer.bar` 单槽位完整替换；完整替换必须重新通过输入法、附件、快捷键、权限、模型、停止和无障碍回归，不能为了截图牺牲功能。

### B. 按钮与图标控件

- 定义 `primary / secondary / quiet / icon / destructive` 五种按钮。
- 每种按钮实现 default、hover、pressed、focus-visible、disabled、busy 六态。
- quiet/icon 按钮不常驻厚重底色，悬停时才凝聚出玻璃底。
- 所有图标继承文本色；不得复制 Apple 的 SF Symbols，继续使用 DSH 自有图标或开源图标。
- 发送、审批等关键按钮必须同时通过颜色、形状和文案表达状态。

### C. Select、Toggle、Slider 与表单

- 自绘 toggle：玻璃轨道、内部亮斑、开关位移、键盘焦点和 disabled 态；隐藏原生 checkbox 但保留语义和键盘行为。
- select 使用自有玻璃外壳与箭头，菜单仍尽量保留原生可访问行为。
- slider 使用 CSS 变量 `--value-percent` 驱动已完成轨道：
  - 未完成轨道为内凹半透明玻璃；
  - 已完成轨道为低饱和光带；
  - thumb 是带顶部高光与底部折射阴影的玻璃珠；
  - hover 放大不超过 1.06，pressed 略收缩；
  - 数值使用等宽数字并在拖动时提升可见性；
  - Firefox 与 Chromium 分别实现伪元素，保留方向键控制。
- 设置项从“大白卡堆叠”改为分组玻璃面板；分隔线是局部内边缘，不横穿整张卡。

### D. 侧栏与列表

- 侧栏使用独立 `glass-panel`，与内容区通过边缘亮度而非实色分割。
- 新会话按钮改为明确的 secondary glass button。
- 工作区标题、会话条目、时间和操作按钮建立固定收缩顺序。
- hover 是轻微材质凝聚；selected 是更稳定的焦点玻璃片，不使用整块蓝灰填充。
- 收起侧栏时保证图标居中、tooltip 可见、命中区不缩水。

### E. 设置弹窗

- 弹窗外壳、导航区、内容区三层分明；背景遮罩降低饱和度而非只增加模糊。
- 当前导航项使用小型焦点玻璃片，与侧栏选中态一致。
- 顶部兼容提示改为状态 banner，减少橙色大块面积。
- Header、关闭按钮、导入壁纸、恢复默认、诊断导出统一到按钮系统。
- 720px 以下改成单列或抽屉布局，避免导航与内容共同挤压。

### F. 会话内容、工具和状态

- 正文区域保持最高可读性，不把每段消息都套玻璃。
- 工具行、审批、错误、目标条和完成回执使用共享 card 原语。
- 状态胶囊从“右下角独立通知”降级为辅助状态岛；默认不遮挡内容和 composer。
- `idle -> thinking -> tool-running -> approval -> success` 使用共享光源、颜色过渡和尺寸变形，但 reduced-motion 下立即切换且信息不丢失。

### G. 多插件 Agent 模式菜单

- 菜单高度不得随 preset 数量无限增长，使用视口约束与内部滚动。
- 每项名称保持单行，描述最多两行；长中文、英文和插件生成说明均不得撑宽菜单。
- 滚动条、hover、键盘焦点和按压状态使用 Glass Control 原语。
- 菜单在 560px 以下占用可用宽度，但必须保留 8px 安全边距。
- 当前 DSH `PresetMenu` 没有搜索或过滤插槽；V2 不向 React 管理的 portal 强插搜索框。真正搜索列为上游 API 增强项，在获得正式接口前以紧凑可滚动列表交付。

## 文本与溢出规范

| 场景 | 规则 |
| --- | --- |
| 会话/工作区标题 | 单行省略；保留完整 `title` 或可访问 tooltip |
| Composer 模型名与权限 | 先缩短辅助文案，再省略主标签；发送按钮不被挤出 |
| 状态胶囊标题 | 单行；说明最多两行，超过后省略 |
| 设置项标题/说明 | 桌面允许两行说明；小于 560px 时控件换到下一行 |
| 数值与单位 | `white-space: nowrap`、`font-variant-numeric: tabular-nums` |
| 工具路径/命令 | 中间省略或可横向滚动，不挤压状态与操作按钮 |
| 中文/英文长词 | 正文 `overflow-wrap: anywhere`；标识符和路径单独处理 |

通用 flex/grid 子项必须显式设置 `min-width: 0`。任何省略都必须能通过 tooltip、展开或详情面板看到完整内容，不能把信息永久截断。

## 技术可行性分层

### Tier A：官方接口，强兼容

- `ctx.theme.overrideTokens`：颜色、基础表面、文字、边界层级。
- `shell.overlay`、`conversation.composer.dock`、`settings.section` 等官方 Slot。
- DSH 原生会话投影与状态数据。
- 插件自己拥有的设置控件、状态卡和浮层可完全重构。

### Tier B：稳定语义属性兼容层，可接受但必须设版本门

DSH 0.1.0-rc.6 已在原生输入区提供：

- `[data-composer-card]`
- `[data-input-scroll]`
- `[data-input-backdrop]`
- `[data-input-mirror]`
- `[data-composer-seat]`
- `[data-shell-overlay]`
- `[data-sidebar-collapsed]`

V2 可只在 `:root[data-dsh-os26='on']` 下使用这些属性，避免 hashed class。兼容层必须：

- 绑定已测试的 DSH 版本范围；
- 启动时检测关键标记，不存在则关闭对应增强并显示兼容提示；
- 不使用全局 MutationObserver，不轮询 DOM；
- 关闭插件后无残留；
- 每次 DSH 升级运行结构契约测试和截图回归。

### Tier C：需要完整替换或上游新增 Slot

- 原生 composer 的 DOM 结构若无法通过 Tier B 达到目标，可占用官方 `conversation.composer.bar`，但这等同于接管完整输入组件，风险最高。
- 侧栏所有原生按钮、设置弹窗外壳、通用弹出菜单若没有稳定语义钩子，不用语言相关 `aria-label` 或结构序号硬套样式。
- 对无法安全覆盖的区域，优先向 DSH 提交 `data-component/data-variant` 或 primitive token 提案；未获得稳定钩子前只做 Token 级优化。

## 实施阶段

### Phase 0：基线冻结与设计样张

- 保存当前浅色、深色、设置页、长标题、多行输入和运行态截图。
- 制作一张静态目标样张，先确认中性画布、composer、侧栏和设置页的整体关系。
- 建立 V2 组件清单和状态矩阵。

**退出条件：**目标样张不依赖专有 Apple 素材，且一眼能看出 composer、按钮、slider 已属于同一系统。

### Phase 1：材质 Token 与全局去蓝

- 重写 `material.js` 和基础 Token。
- 建立五级 Glass Primitive，移除全屏淡蓝洗色。
- 完成浅色、深色、无透明和 Eco 回退。

**退出条件：**关闭壁纸仍有清晰层级；开启壁纸只局部透色；正文对比达到 WCAG AA。

### Phase 2：Composer Hero

- 先用 Tier A + Tier B 重塑原生 composer。
- 覆盖输入、工具行、模型、权限、发送/停止、附件和状态联动。
- 评估是否仍需要完整 `conversation.composer.bar` 替换。

**退出条件：**默认、多行、运行中、审批、禁用、附件、窄屏和 200% 缩放全部通过；输入法和快捷键无回归。

### Phase 3：控件系统与设置页

- 完成按钮、toggle、select、slider、focus ring。
- 重排设置分组与移动端布局。
- 修复全部插件自有文字溢出。

**退出条件：**鼠标、键盘和触屏均可操作；slider 在 Chromium/Firefox 一致可读；系统 reduced-motion/transparency 生效。

### Phase 4：侧栏、列表、内容卡和状态整合

- 只对存在稳定边界的原生区域使用 Tier B。
- 统一会话条目、工具卡、目标条、状态岛和 modal 层级。
- 删除重复或无价值的装饰性胶囊。

**退出条件：**1440px、1024px、768px 三档无溢出；长中文、长英文、长路径和大字体不遮挡操作。

### Phase 5：视觉回归与性能硬化

- 建立 Playwright 截图基线：浅/深、三种视口、六种 composer 状态、设置页全部控件状态。
- 添加 DOM 契约检测、溢出扫描、对比度检查和关闭残留检查。
- 测量 blur 区域、动画帧和滚动性能；低性能设备自动使用 Eco。

**退出条件：**无 P0 视觉差异、无横向溢出、无不可见焦点、滚动无持续高开销。

### Phase 6：发布与视频门禁

- 从最终 tarball 在干净 profile 安装，不从源码目录录屏。
- 请第二个人按 README 安装并完成真实会话。
- 视频展示真实输入、执行、审批和完成，不使用假状态。
- 发布文案使用“iOS 26-inspired / Liquid Glass-inspired”，不宣称 Apple 官方、像素级复刻或首个同类。

**退出条件：**产品截图与视频均来自同一发布包；已知限制公开；卸载可恢复原 UI。

## 当前实施状态（2026-08-16）

本节只记录已经取得的证据，不降低各 Phase 的退出条件：

- Phase 1–4 的主要实现已进入发布候选包：Composer、按钮、toggle、select、slider、侧栏、模式菜单、工具卡、目标条、审批、问题与计划审阅使用统一分层玻璃体系；正文、代码和 Diff 保持阅读面。
- 文字溢出、稳定语义钩子、关闭清理、reduced-motion、reduced-transparency、Eco 与无 `backdrop-filter` 回退均已有自动化覆盖；当前测试为 47/47。
- 最终安装包上的真实 agent、审批允许/拒绝、用户问题与计划审阅流程已经通过；原生决策面消失后焦点回到 Composer，浏览器 AX Tree 的 heading/radio/button/checked/disabled 语义通过。
- 1440/1280/768 等布局及 effective-200% 布局自动化已通过，但不能替代实际浏览器 Ctrl+ 200% 人工检查。
- Phase 6 尚未完成：真实屏幕阅读器、第二位使用者独立安装/任务/卸载、发布前 24 小时撞名复查、最终包录屏以及 npm/GitHub 发布仍是明确门禁。

## 自动化验收矩阵

至少覆盖以下组合：

- 主题：light、dark、system、opaque；
- 质量：Eco、Balanced、Cinematic；
- 视口：1440×900、1024×768、768×900；
- 缩放：100%、125%、200%；
- Composer：空、长文本、多行、附件、running、approval、blocked、error；
- 控件：default、hover、pressed、focus-visible、disabled；
- 文本：长中文、无空格英文、长路径、超长模型名；
- 环境：Chromium、Edge、Firefox，reduced-motion、reduced-transparency。

新增硬门禁：

1. `scrollWidth <= clientWidth + 1` 的区域级溢出检查。
2. 关键操作在 200% 缩放下仍可见且可达。
3. 所有 `text-overflow: ellipsis` 节点存在查看完整内容的路径。
4. 关键语义属性缺失时增强安全降级，不出现半套样式。
5. 插件关闭、禁用和卸载后，Token、样式节点、data 属性和监听器全部清理。

## 本轮明确不做

- 不复制 Apple 壁纸、字体、SF Symbols 或系统截图。
- 不为了“更像”重做与 DSH 无关的假控制中心、Dock、锁屏。
- 不使用 hashed class、`nth-child`、中文 `aria-label` 等脆弱选择器。
- 不用强模糊掩盖组件设计问题。
- 不在视觉验收完成前发布正式宣传视频。

## V2 Definition of Done

只有同时满足以下条件，V2 才可录制发布视频：

- composer 是画面主视觉，并且真实输入功能零回归；
- 按钮、toggle、select、slider、卡片和 modal 属于同一材质系统；
- 页面不再有全屏淡蓝洗色，层级由局部玻璃和中性画布建立；
