# DSH-OS26 发布视频计划

## 视频定位

这是产品发布短片，不是概念渲染。核心信息只有一句：

> DSH-OS26 的液态玻璃会响应真实 Agent 状态，不只是透明和模糊。

初始假设：主版本为 35-45 秒、9:16、中文硬字幕，适合短视频平台；
另导出一个 16:9 版本用于 GitHub README、B 站或 YouTube。正式制作前再确认平台、
时长和是否需要旁白。届时视频制作按 HyperFrames 的 product-launch-video 工作流执行，
当前文档不等同于最终 `BRIEF.md`。

## 发布前提

以下任一条件不满足，就不拍正式发布片：

- 视频中的插件来自准备发布的 npm tarball，而不是单独的演示分支。
- 所有状态由真实 DSH 任务触发；手动状态模拟只能出现在标注为“设计预览”的片段。
- 安装命令由另一台或干净 Profile 验证过。
- 性能、兼容性和已知限制已经写入 README。
- 没有使用 Apple Logo、SF Symbols 拷贝、系统壁纸或未经授权的系统音效。

## 镜头结构

### 0-3 秒：钩子

- 画面：原生 DSH Web。
- 操作：打开 DSH-OS26 开关，界面进入玻璃材质。
- 字幕：`我给 DeepSeek Harness 做了个 OS：DSH-OS26`
- 要求：切换必须是真实插件设置，不做后期假切换。

### 3-8 秒：证明不是普通毛玻璃

- 更换一张高对比壁纸。
- 鼠标移动经过边缘，展示高光、折射和可读性补偿。
- 同屏快速切换 Eco / Balanced / Cinematic。
- 字幕：`不是套一层 blur`

### 8-14 秒：思考状态

- 输入一个短而确定的真实任务。
- 状态胶囊由 idle 连续过渡到 thinking。
- Composer 和状态材质共享同一节奏，不要全屏乱动。
- 字幕：`玻璃会读懂 Agent 状态`

### 14-21 秒：工具执行

- Agent 调用可控的测试工具或 Bash fixture。
- 工具活动面从 Composer 附近连续生长，而不是突然弹窗。
- 展示真实工具名和运行时间。
- 字幕：`调用工具时，界面开始流动`

### 21-28 秒：审批高潮

- 使用专门的安全 fixture 触发一次无破坏性的审批请求。
- 材质凝结、边缘变暖，审批操作保持官方语义。
- 用键盘完成批准或拒绝，证明不是不可操作的概念稿。
- 字幕：`需要你决定时，它会停下来`

### 28-34 秒：完成回执

- 显示真实成功结果，例如 `12 tests passed`。
- 工具活动收束为完成回执，动画归于平静。
- 字幕：`完成后，过程沉淀成一张回执`

### 34-40 秒：可信收尾

- 展示安装命令和 GitHub 仓库名。
- 角落标注：`Open source · No telemetry · Uninstall restores stock UI`
- 结尾标题：`DSH-OS26 — Agent-reactive Liquid Glass`

## 可重复演示任务

为视频维护一个不会接触真实项目的 `demo/fixture`：

1. 读取一个小文件。
2. 运行一个 1-2 秒的确定性测试。
3. 请求一次安全审批，例如写入 fixture 内的临时结果。
4. 输出固定的通过数量和一份完成回执。

正式录屏不得使用 `rm`、真实凭据、网络部署或真实用户仓库制造审批画面。

## 画面与声音

- 屏幕录制至少 1440p、60 fps；最终 9:16 版本重新构图，不直接裁掉关键 UI。
- 壁纸使用自制或明确可商用素材，并在仓库记录来源。
- 音效只强化状态转变，不模仿或盗用系统原声。
- 音乐不是必须；如果使用，节奏不能盖过真实 UI 声音和字幕。
- 中文硬字幕保持每行不超过约 16 个汉字，避免覆盖 Composer 和审批按钮。
- 不用“科技蓝粒子 + 假代码 + 巨量 Bloom”掩盖产品本身。

## 容易被骂的点与应对

| 可能评论 | 发布前用产品和视频回答 |
| --- | --- |
| `不就是 backdrop-filter？` | 用移动背景近景展示真实折射，并展示三档材质参数。 |
| `抄 Apple` | 使用原创图标、壁纸和动效；文案明确 inspired、非官方，不宣传像素级复刻。 |
| `已有一堆液态玻璃插件` | 在 README 致谢先行项目，重点展示“全局材质由 Agent 状态驱动”。 |
| `只能拍视频，日常没法用` | 视频中展示 Balanced/Eco、减少动画和不透明模式。 |
| `状态都是假的` | 录制真实 DSH 事件；开发诊断层可显示当前状态来源。 |
| `GPU 烧起来了` | 发布性能测试方法；Cinematic 非默认，后台标签页停止渲染。 |
| `装完卸不干净` | 片尾或置顶评论给一行卸载命令，并有自动化卸载测试。 |
| `会不会偷数据` | 插件无网络、无遥测、无凭据读取，并在仓库列出安全边界。 |
| `一更新就坏` | 写明测试的 DSH 版本和 commit，不宣称支持所有版本。 |

## 禁止在视频中使用的说法

- `全网首个 DSH 液态玻璃`
- `100% 还原 iOS 26`
- `零性能损耗`
- `兼容所有 DSH 插件`
- `DeepSeek 官方主题`
- 没有测试证据的 FPS、内存或体积数据

## 发布物料

- 9:16 主视频。
- 16:9 GitHub/B 站版本。
- 6-10 秒无声循环 GIF/WebM。
- 亮色、深色、审批、完成四张真实截图。
- 性能测试截图及测试环境。
- 一条复制即用的安装命令。
- 一条复制即用的卸载命令。
- 置顶评论：兼容版本、已知限制和非官方声明。

## 发布顺序

1. npm 发布 beta。
2. 从 npm 安装并重新跑 smoke test。
3. GitHub Release、README、截图上线。
4. 再录制或复核正式视频，确保画面与发布包一致。
5. 视频上线，置顶安装、卸载、兼容性和免责声明。
6. 48 小时内只修 P0/P1 问题，不被评论推动着临时堆功能。
